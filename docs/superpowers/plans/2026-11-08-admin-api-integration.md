# Admin ↔ API Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the mock data and fake login in `front-end/admin` with the live Laravel API, using the layering in `frontend-data-fetching.md`, and add a small and a full-screen loader in the site's colours.

**Architecture:** Component → `hooks/use-*.js` (React Query, toasts, invalidation, mapping) → `api/*.js` (one function per endpoint) → `lib/api-client.js` (token, 401, error toast). Local mock stores are removed module by module; screens keep their current design.

**Tech Stack:** React 19, Vite 8, react-router-dom 7, `@tanstack/react-query` v5, axios, Vitest + Testing Library + `axios-mock-adapter`. Backend: Laravel + Sanctum bearer tokens.

**Spec:** `docs/frontend-data-fetching.md` (added in Task 1). API contract: `backend/routes/api.php`, `backend/public/docs/openapi.json`.

## Global Constraints

- All work is in `front-end/admin`, on branch `feature/api-integration`. The public site (`front-end/src`) has no API-backed feature and no public endpoint exists, so it is out of scope.
- Files are `.js`/`.jsx`; this project has no TypeScript.
- API base: `import.meta.env.VITE_API_URL ?? '/api'`. Dev proxies `/api` to `https://ibram.apps.taqat.academy` because staging sends no CORS header for `localhost`.
- `staleTime: 0`, `gcTime: 0`, `placeholderData: keepPreviousData`, `retry: false`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`.
- Visible text is written in Arabic and any new string gets an entry in `admin/src/i18n/en.json`; the DOM translator handles English.
- Any new CSS file in `src/styles` must be registered for both RTL and LTR in `src/styles/loader.js`; `styles-ltr` is generated by `npm run gen:ltr`.
- Colours come only from the `:root` tokens in `styles/global.css`.

### Where the MD does not match this backend

| MD says | Here | Decision |
| --- | --- | --- |
| `ApiResponse.data` / `isSuccess` envelope | Raw JSON, Laravel paginator, some lists wrapped in `{ data: [] }` | Client returns `response.data`; API functions unwrap `{ data }` lists |
| Token refresh and retry | No refresh endpoint; tokens never expire but can be revoked | 401 clears the session and goes to `/login` |
| `api.get/post/put/delete/getBlob` | Backend relies on PATCH; no current screen downloads files | Add `api.patch`; add `getBlob` with the first attachment screen |
| `Accept-Language` | Sent, but the backend has no locale middleware, so messages are mixed Arabic/English | Keep the header; screens that need a fixed message use `silent` |
| `@msbes/data-table`, `useLookup`, `useTranslation`, `useNotify` | None exist | Per-module `useQuery` for lists; `useNotify` is built in Task 2; Arabic literals instead of `t()` |

### Out of scope: no backend support

Left on mock data and not wired: Items, Units, Categories, Forgot/Reset Password, First-Login Password (no must-change flag), Create Role, notification preferences, procurement settings. The API's purchase-request, RFQ, quotation, bid-opening, report and notification endpoints have no admin screen yet, so they need designs first.

## Review Focus

1. A token revoked mid-session (user deactivated or password reset) with several calls in flight → exactly one redirect to `/login`, no toast, no loop. Test in Task 1.
2. A 422 with field errors or a supplier `duplicates` list → the user sees the specific reason, not "The given data was invalid". Tests in Tasks 1 and 7.
3. Overlapping and very fast calls → full-screen loader stays until the last call ends and does not flash under 200ms. Test in Task 2.
4. An account without `users.manage`, `audit.view` or `settings.manage` → page renders, restricted calls are not sent, no 403 toast storm. Test in Task 9.
5. Null `department`, `phone`, `email` or empty lists → rows show `—`, no crash. Test in Tasks 4 and 7.
